# Bum Bum E2E suite (Playwright)

End-to-end tests for [leaveittobumbum.com](https://leaveittobumbum.com).
The full rationale, tiers, data rules, and coverage matrix live in
[`docs/e2e-test-plan-2026-10-26.md`](../docs/e2e-test-plan-2026-10-26.md).
This README is the how-to.

## Quick start

```bash
cd tests-e2e
npm install
npx playwright install chromium
npm run fixtures        # builds the tiny media files in fixtures/ (needs ffmpeg)
npx playwright test     # smoke projects against staging, by default
npm run report          # open the last HTML report
```

> **Sandbox VM note:** inside the REN VM, Chromium can't use the egress
> proxy directly. Start runs with `LOCAL_PROXY=http://127.0.0.1:18080`
> (global-setup auto-starts `scripts/local-proxy.mjs`, which performs the
> upstream CONNECT and pipes bytes, and the config relaxes cert checks
> for the proxy's MITM CA — sandbox only, never set in CI).

## Environments

| Target | How | What may run |
| --- | --- | --- |
| Staging (default) | *(nothing to set)* or `BASE_URL=https://staging.leaveittobumbum.com` | Everything |
| Production (read-only) | `BASE_URL=https://leaveittobumbum.com` | **Smoke projects only.** The config refuses to define the weekly/billable projects against production: those file records and spend actions. |

Staging is a subfolder of the production site and **shares the production
database** — treat every staging write as a production write (see the data
rules in the test plan).

## Tiers

```bash
npm run test:smoke     # specs/smoke/    public pages, blog, footers (desktop + mobile)
npm run test:weekly    # specs/weekly/   desk routing, handoffs, all 21 tools, guest prompt
npm run test:billable  # specs/billable/ AI happy paths + Stripe test checkout (spends money-adjacent things)
```

- **Smoke** runs anywhere, any time. Safe against production.
- **Weekly** is the Monday workflow's tier. It files a handful of tiny
  guest records (the approved routing set) and runs the client-side tools
  for real. Video specs carry an `@slow` tag:
  `npx playwright test --project=weekly --grep-invert @slow` for a fast pass.
- **Billable** only exists when `E2E_BILLABLE=1` (the npm script sets it).
  One real Groq/vision/transcription run per AI tool, plus the Stripe
  test-mode checkout. Run it deliberately, e.g. after touching an AI tool,
  not on a schedule by default.

## Test account

Specs that must be signed in (billing) read credentials from the
environment and **skip with a clear message when they are absent**:

```bash
export E2E_TEST_EMAIL="…"        # dedicated test account, never a personal one
export E2E_TEST_PASSWORD="…"
```

In GitHub Actions these come from the `E2E_TEST_EMAIL` /
`E2E_TEST_PASSWORD` repository secrets.

## Weekly workflow

`.github/workflows/e2e-weekly.yml` runs Mondays 14:00 UTC against staging
(smoke + weekly projects) and uploads the Playwright HTML report as a
build artifact. Manual dispatch can pick the suite and optionally enable
the billable tier. It is intentionally **not** chained to deploy workflows.

## Fixtures

`scripts/make-fixtures.mjs` generates everything the uploads need with
ffmpeg: a drawn receipt/poster/meal PNG, a 64px PNG, a 2s tone WAV, an MP3
(spoken sentence when ffmpeg has the `flite` filter, tone otherwise), a 2s
MP4, and a hand-built one-page PDF resume. Fixtures are git-ignored and
regenerated by `global-setup.ts` when missing.

## House rules for new specs

- Assert what the visitor sees (real DOM, real ids from the source), not
  internals. No fixed `waitForTimeout` sleeps; Playwright's auto-waiting
  and `expect.poll` cover the slow bits (the desk's 4s crossing included).
- A fresh browser context per test = a fresh guest. Guest-minting is
  capped per IP per day, so keep filing tests few and purposeful.
- If a spec fails because the SITE is wrong, the spec is right: file the
  finding, do not bend the spec to the bug.
